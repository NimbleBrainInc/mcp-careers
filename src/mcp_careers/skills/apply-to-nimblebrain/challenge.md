# The challenge: build a skill

Build a skill that makes an agent good at something real from your own work, and tell us
what your agent got wrong while you built it.

## What to send

- **`skill`**: the whole `SKILL.md`, frontmatter included (`name` and `description`), up to
  20,000 characters. Pick something you would actually use: a task you repeat, a judgment
  call you make, a system you know better than anyone. Build it with your agent and test it
  on a real case.
- **`note`**: 50 to 300 words, written by you, not your agent. What did your agent get
  wrong while you built the skill? How did you catch it? What would you change with another
  day?

## What we look for

- **The skill tells an agent when to use it**, not only what it is about. Its `description`
  is what an agent reads to decide whether to load it.
- **It tells the agent what to do**, including what to do when something goes wrong.
- **It is specific.** A skill that would read the same for anyone's work is a weak one.
- **The note is honest and concrete.** Name the mistake. The note matters as much as the
  skill.

## How it is read

A person on the NimbleBrain team reads every submission. Nothing is scored automatically.
If it is a fit, we email you to set up a conversation, which is where we go deeper.
